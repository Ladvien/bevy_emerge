## Enhancement: `piece_set_mount`
Goal: an agent can say where a library piece goes, and `M`, the chip and the agent are one validated, saved, logged and undoable change.
Files: `ops.rs` (`piece_set_mount`, registry row, `UI_ENTRY_POINTS` row, bare-undo scope), `editor.rs` (`set_mount`), `tiles.rs` (`step_mount`, `rebuild_from`, `check_measured`), `keys.rs` (`CycleMount => piece_set_mount`).
Proof: `tests/piece_set_mount_is_an_operation.rs` (4 tests). The first three failed on the base (`no operation` for an agent; `one press of M is one log line` left 1, right 2: `M` logged nothing); the fourth, the bare undo, failed on the old scoping (`left: 110.0 right: 0.0`: the turn stayed, the mount was undone). 27 passed on big with `operations_have_two_front_ends::` (8) and the label, undo and chip tests; the real push gate (clippy and `cargo test --workspace`) ran on big.
MCP: `piece_set_mount` (`id`, `mount`), `Undo::Inverse` restoring the mount and the label record, `writes_library` so its line joins the Meshes history. Refusals, all before anything is written: an unknown id (closest ids named), another kit's piece, a mount the project does not offer (the refusal lists every rung as a label and as JSON), a negative or non-finite height, an unknown field, an agent's own `restore`, and anything `check_measured` would refuse at commit (a surface class no piece offers).
Decision: `M` steps past a rung the library would refuse. Before, the rung was written in memory, the file refused ("NOT WRITTEN") and `M` walked on; with the write now atomic, stopping on the first refused rung would have stuck the key. The step asks `check_measured` so no refusal is logged for a rung nobody chose.
