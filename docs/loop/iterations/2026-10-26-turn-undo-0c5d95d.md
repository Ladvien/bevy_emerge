## Summary

E-071 made an agent's presented turn one `Undo::Group`, so a person's Cmd+Z takes the whole turn back.
`emerge_undo_operation` with no id walks the operation **log** and takes back one logged change — right
for what it says, but it meant **the same turn came back in two amounts depending on who asked**:
measured live on Sanctuary's `town`, 730 → 729 for the agent's tool where Cmd+Z leaves 727.

`turn: true` is the missing verb. It walks the presentation's ids newest-first through the same
`ops::undo(ctx, Some(id))` the id form makes, so there is no second undo mechanism and the log stays
the only writer. After: `took_back: 3`, 730 → **727**, `undo_depth: 0`.

## Enhancement: an agent can take the whole turn back

**User-facing goal:** an agent that presented three changes can take all three back in one call, the
same amount the person's Cmd+Z takes.

**Plan:** a `turn` flag on `emerge/operation_undo` that walks the presentation's ids, newest first.
**Files:** `crates/bevy_emerge_mapper/src/ops_brp.rs` (`UndoParams::turn`, the loop),
`crates/bevy_emerge_mcp/src/main.rs` (the param, the description, and the hand-built body),
`src/docs.rs` (description + schema), `docs/mcp-tools.md` (regenerated),
`tests/an_agents_turn_is_one_undo_step.rs` (three new tests).

**MCP:** `emerge_undo_operation` gains `turn: bool`, default `false`, documented in the description
and the schema. The answer gains `took_back` (how many changes the turn took) and `stopped`. Preview
still writes nothing: `turn` with `dry_run` answers the ids it would walk and `would_take_back`.

**Two design decisions worth stating:**

- **A flag, not a change to the id-less form.** An undo on the log is well defined with no
  presentation, survives a door crossing, and is what `emerge_read_oplog` lists. Making it silently
  depend on a UI resource would make one call mean two things on two screens. The person's Cmd+Z has
  always meant "the turn", so the agent's door gains that verb rather than changing what its existing
  one says.
- **Refused when nothing has been presented.** A turn is a thing the agent declared; with no
  declaration there is nothing to take back as one, and falling back to "the newest change" would be
  the ambiguity this flag exists to remove.

**Candidates considered and not chosen:** E-083 (Sanctuary's compositions are all `Anchored`, so the
composed source cannot run there) and E-082 (`rules_set` cannot check descriptor ids against a library
it does not have). Both are still open and neither is a one-iteration fix.

## Live proof on the real project

Three `placement_add` operations on Sanctuary's `town`, a presentation, then **one** `turn: true`:

```
turn undo: {"operation": "undo", "outcome": "applied", "stopped": null, "took_back": 3}
placements: 730 -> 727
undo_depth: 0
```

`730 → 727` is three placements, the same amount Cmd+Z takes, and `undo_depth: 0` says the turn's
group went with them rather than being left as a stale entry.

| **3. | **4. Does the single-change undo still work?** | Yes — `one_change_can_still_be_taken_back_on_its_own` pins that the id and id-less forms are unchanged, and that the person's next Cmd+Z takes the remaining two (because `forget_line` removes the agent's one from inside the group). |
| **5. Is the refusal honest?** | Yes: `a_turn_undo_with_no_presentation_is_refused` asserts both the refusal and that the map did not move. |
