## Bugs fixed
### #165: relations read a map's yaw as radians
Must-fix: blocks y, common y, no workaround y — a map stores yaw in degrees (`place` schema "Facing in degrees", the spawner's `to_radians`, fixtures at 90/180), while `relations::check`/`solve` read radians and the editor passed map rows straight in. A lamp in front of a door at `yaw: 180.0` read `unmet, measured 1.197`; solving `Faces` wrote `1.5707964` into a degrees field.
Root cause: no unit boundary between map rows and the relation layer. Fix: `relations::check_map`/`solve_map` take map rows (degrees) and hand back degrees, leaving rows the solve did not turn bit for bit; the editor's three callers (`ops_relations::mend`, `ops_brp::relations_json`, `relations_readout`) and `session::score` use them. Assumed decision on #165: a core boundary, not a unit change in `check`/`solve`, because protected relation tests pin radians.
Regression check: `bevy_emerge_mapper/tests/relations_read_a_turned_piece_in_degrees.rs` (2 tests; before: `left: 1 right: 0 … measured 1.1969` and `the table is on +x, 90 degrees: 1.5707964`; after: pass). Found by the reviewer over ab5a504.
