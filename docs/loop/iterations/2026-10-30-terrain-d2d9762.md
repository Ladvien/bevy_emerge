# 2026-10-30 terrain: a terrain file that does not fill its shape is refused, not indexed (#187)

Focus: bug issue #187 · Commits: d2d9762 (fix) + docs · Machine: laptop (mac_air) · Outcome: fixes only

## Summary
`Heightfield` was deserialised from `terrain/<map>.ron` with a bare serde derive, so 3 heights for a 4x4 field panicked the editor in `ground_mesh` and inside `terrain_stroke`. Core now has `Heightfield::parse`/`validate`, and every terrain reader goes through it: the view draws no ground and names the file on the status line, `terrain_stroke` and `water_run` refuse, piece heights and `forest_place` treat it as flat ground.

## Baseline
Gate: clippy `-D warnings` on core and mapper (all targets) green; the push gate runs the workspace tests. `accept.py`: not run this pass (see Acceptance). Load 4.77 at start, free disk 27 GB, 32 GB RAM.

## Bugs fixed
### #187: a terrain file whose heights do not fill width x depth panics the editor
Must-fix: blocks y (the editor panics on open), common n, no workaround n (deleting the file loses the terrain). Blocks, so must-fix.
Root cause: no validation between the file and the indexers (`heightfield.rs` `at`/`dab`, `terrain_view::ground_mesh`, `water::simulate`).
Regression checks: `bevy_emerge_core/tests/a_terrain_file_that_does_not_fill_its_shape_is_refused.rs` (5 tests; before the fix it did not compile, `Heightfield::parse` did not exist); editor `a_terrain_file_that_does_not_fill_its_shape_is_refused::it_draws_no_ground_and_the_status_line_names_the_file` and `::a_stroke_on_it_is_refused_and_writes_nothing`, 2/2 pass. An honest editor "before" run was not possible: the first run picked up the half-applied fix (compile error), and a base worktree build did not fit the budget. The issue's own evidence (`index out of bounds: the len is 3 but the index is 4`) is the before.
Related terrain tests still pass: `terrain_stroke_is_an_operation`, `water_run_settles_a_pond`, `pieces_stand_on_sculpted_ground`, `volume_edit_is_an_operation`, `forest_stroke_is_an_operation`, `terrain_view_draws_water` (11/11).
