# 2026-10-26 rules: an agent can read the rules a layout is generated from (E-073)

Focus: describe → set up → inspect (the agent inspects its own generated layout) · Commits: `0597d83` · Outcome: shipped

## Summary

The loop's Inspect step asks two things of generated content: which constraint shaped the layout, and
how varied the seeds were. Neither is answerable by an agent that cannot see the rules, and no tool
could name a single field of them. Sanctuary's `rules.ron` states
`weights: [(prefix: "town/house_", times: 100.0)]` over a 17×17 block with four minimum footprints —
the numbers that decide what its town looks like — and the file was reachable only by reading it off
disk.

`emerge_list_rules` answers every block whole, with the path it read, through the editor's own
`Project::open` path and parser.

The write half of E-073's title ("read **or change**") is not in this iteration. It is filed as
**E-081** rather than claimed: changing a weight still needs a text editor, and a `rules_set` that
rewrites a commented RON file needs the `rules_renamed` text-rewrite treatment, which is its own
iteration's worth of care.

## Enhancement: an agent can read the rules

**User-facing goal:** an agent that generates a layout can say what shaped it and which number to
change, without a person opening a text editor.

**Plan:** one read tool over `assets/emerge/rules.ron`, parsed with the editor's own schema.
**Files:** `crates/bevy_emerge_mcp/src/main.rs` (`list_rules`), `src/docs.rs` (the `ToolDoc` and its
schema), `Cargo.toml` (one dependency), `tests/an_agent_calls_the_server.rs` (two tests),
`docs/mcp-tools.md` (regenerated).

**MCP:** `emerge_list_rules` added, `readOnlyHint: true`, `destructiveHint: false`,
`idempotentHint: true`, no parameters. It reads a file, so it needs no editor running and is not an
operation, not logged and not undoable — the same contract `emerge_list_snips` has.

**Three behaviours worth stating:**

- **An absent file is no blocks, not a refusal.** `Project::open` treats it the same way; an agent
  told "broken project" for a project that simply states no rules would hunt a bug that is not there.
- **A file that does not parse is refused by name**, with the parser's reason and its path, and
  nothing written. Reading it as an empty answer would let an agent report a layout that had nothing
  to do with what the person wrote — the loop's "bad data never reads as an empty answer" rule.
- **It is the editor's own parser.** `bevy_emerge_core` is a new dependency of the server precisely
  so there is not a second copy of the rules schema; `bevy_emerge_core` is engine-free, which
  `tests/engine_free.rs` guarantees.

**Candidates considered and not chosen:**

- *A `rules_set` write operation* (now E-081): the higher-value half, and bigger than it looks — a
  commented RON file needs `rules_renamed`'s text-rewrite treatment, and `rules.ron`'s comments are
  the reason `map_rename` does not re-serialize it.
- *Turn checkpoints, one Cmd+Z per agent turn* (E-071): the Collaboration lens's next row and a real
  friction, but it touches undo grouping across the whole operation layer — a poor fit beside a
  read-only tool.
- *A "picked up" state for a snip* (below): real, but it is a two-sided protocol (the person must see
  the agent took it), so it needs a surface on both ends.

## Test diffs

Two tests added to `crates/bevy_emerge_mcp/tests/an_agent_calls_the_server.rs`; no existing test or
assertion changed anywhere.

- `an_agent_can_read_the_rules_a_layout_is_generated_from` — **failed before** with
  ``"`emerge_list_rules` is not a tool this server has. The tools are: emerge_apply_operation, …"``,
  passes after. Also pins the absent-file case.
- `a_broken_rules_file_is_refused_by_name` — **failed before** for the same reason, passes after.
  Pins that the refusal names `rules.ron` and leaves the file as it was.

**One fixture bug of mine, recorded:** the first version of the rules fixture wrote
`border: "town/wall_segment"` where the schema takes `Option<String>`, so the parse refused it
(`rules: 9:20-9:21: Expected option`). The tool was right and the fixture was wrong; it now writes
`Some("town/wall_segment")`.

**One real gap the ratchets caught:** the first draft added a `ToolDoc` and a tool but no entry in
`docs::schemas()`, and `docs_are_current::every_tool_has_a_schema` failed with *"the tool
`emerge_list_rules` has no parameter schema, so an agent cannot tell what to send it."* Fixed by
declaring the empty-object schema, not by relaxing the test.

## Deferred / open

- **E-081** — an agent can read the rules but still cannot change one.
- **Found during the focus probe, not filed as a defect but worth naming:** a snip has no *picked up*
  state. `emerge_list_snips` answers the person's note and the placements inside the rectangle, but
  nothing marks a snip as taken, so two agent sessions can act on one request and the person cannot
  tell from the editor whether their note was read. That is a two-sided surface (the person must see
  the agent took it), so it is a candidate for a future Collaboration iteration rather than a bug.
- The note a person types is one line capped at 200 characters (`snip.rs::NOTE_CAP`). A request like
  "make these two a mossy gate, keep the wall behind them, and leave the road clear" is already at
  the edge of that. Named here because the focus is that note.
