## Enhancement: a proposal says how varied it is

**User-facing goal:** an agent that generated a layout can report how much of it is enclosed and how
many rooms it holds, so a person can compare seeds instead of looking at one.

**Plan:** carry `Solved`'s grid, size and interfaces into `Proposed`, score them with
`range::measure`, and put the numbers in `layout_propose`'s answer.
**Files:** `crates/bevy_emerge_core/src/grammar.rs` (`interfaces`), `crates/bevy_emerge_mapper/src/editor.rs`
(`measure_solved`, `Proposed::variety`, `Proposed::cells`), `src/ops.rs` (the answer's `variety`),
`src/checks.rs` (a stale note), `tests/a_proposal_says_how_varied_it_is.rs` (new).

**MCP:** no new tool. `layout_propose`'s preview answer gains `would_change.variety`:

```json
"variety": {"enclosure": 0.6953125, "regions": 67, "opening_density": 0.0, "cells": 256}
```

`null` when the source derives no wall interfaces. `layout_propose` declares `Undo::None` — a proposal
is not a document change — so there is no undo question here.

**Three design decisions worth stating:**

- **`null` is not `0.0`.** A grammar learned from placements derives no wall faces, so nothing can be
  classified. `0.0` is a *meaningful* enclosure value — "no floor is enclosed" — so a layout that could
  not close anything and one that could and did not must not read the same.
- **A wall-less grammar is also `null`.** `range::Faces::floor` is true for every prototype but the
  empty one, so a composed grammar whose pieces present no `wall` anywhere would score a confident
  `0.0`. `from_compositions` is *expected* to skip such a composition, so this is a belt on top of
  braces; it is there because the failure it prevents is silent and looks like a measurement.
- **`cells` rides beside the measurement.** `Measured` reports fractions and a count of *regions*, not
  of cells, so `enclosure: 0.0` alone cannot distinguish a walled-in empty map from a 16×16 solve that
  enclosed nothing.

**Candidates considered and not chosen:**

- *Turn checkpoints, one Cmd+Z per agent turn* (E-071): the Collaboration lens's next open row and real
  friction, but it touches undo grouping across the whole operation layer.
- *`map_remove`* (E-066): `map_create` declares `Undo::None` because the faithful inverse of a create
  is a removal no operation carries — a new inverse shape.
- *E-082*, `rules_set`'s missing library check: the operation's `Ctx` has no `Library`, so this needs a
  decision about where a library comes from on the server, not a small fix.

## Live proof on the real project

Through the MCP server against a scratch copy of Sanctuary, `town` open:

```
learned   -> laid 5776  variety null
composed  -> refused: "grammar: nothing has been placed yet, so there is no arrangement to continue."
```

**Both results are correct, and the second is a fact about Sanctuary's kit rather than about this
change.** `learned` derives no wall interfaces, so `null` is the right answer. `composed` is refused
because **all 16 of Sanctuary's compositions are `Anchored`** (`Bounded: 0, Anchored: 16` in
`compositions.ron`) and `from_compositions` skips an anchored group by definition — *"it presents no
edge to match"* — leaving a one-prototype grammar that `solve` refuses. **So the one project in this
repo cannot currently exercise the metric at all**, and the measurement is proved on the crate's own
fixture instead. That is worth knowing and is why it is stated here rather than left as "shipped".
