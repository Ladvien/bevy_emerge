## Summary

`main` was red on one test. That failure was the test's own lookup — the Kit door spawns two panels
titled `INSPECTOR`, one hidden, and the helper took whichever came first in ECS order — so the fix is
in the test and the product is untouched.

The enhancement is the brief's own rule: *"Relevant validators run after every mutation. Their
failures appear in the tool result."* An agent's `emerge_apply_operation` answer now carries a
`checks` object naming the edge faults and overlapping placements **the change introduced**, with the
whole map's totals beside them. `"applied"` alone could not tell a `placement_set_yaw` that opened a
seam on the far side of a 720-placement map from one that changed nothing.

Scope is the user's: edge faults and overlaps. The two other parts of E-074 are filed as their own
items rather than half-built — **E-079** (a crate in a doorway, which `stack::blocking`'s own doc
says nothing compares across layers) and **E-080** (variety, which needs the solver grid the editor

## Enhancement: `checks` on every map-changing operation (E-074)

Plan: a whole-map overlap pass in core, a `checks` module in the mapper that diffs two snapshots, and
the same two lines of wiring in **both** front ends. Files: `crates/bevy_emerge_core/src/stack.rs`
(`overlaps` + 3 tests), `crates/bevy_emerge_core/src/adjacency.rs` (`dir_name` public),
`crates/bevy_emerge_mapper/src/checks.rs` (new), `ops_brp.rs`, `sequencer.rs`, `crates/bevy_emerge_mcp/`
(`main.rs`, `docs.rs`, regenerated `docs/mcp-tools.md`).

The answer's shape:

```json
"checks": {
  "edge_faults": {"new": [{"a": "..", "b": "..", "dir": "E", "message": ".."}], "new_total": 1, "total": 3},
  "overlaps":    {"new": [{"a": "crate@0", "b": "crate@1"}],                  "new_total": 1, "total": 1}
}
```

**Four design decisions worth stating.**

- **`new` is the difference, `total` is the map.** An agent told twenty standing faults every time it
  moves a crate learns to ignore the field, which is the same as not reporting them. A finding's
  identity is `(a, b, dir)` for an edge fault and the sorted id pair for an overlap, so a reworded
  message or a reordered file is not a change.
- **A finding is not a refusal.** `outcome` stays `"applied"`; the change happened, and the agent
  decides. Turning a check into a refusal would make a validator the second opinion on a rule the
  click path already enforces.
- **Absence and `null` mean different things.** A preview has no `checks` key at all, because it
  changed nothing and a key would claim a check ran. An operation that touches no document answers
  `"checks": null`. The test pins that difference rather than tolerating either.
- **`map_open` is named literally in `wanted`.** Every other operation is checked because the registry
  says `undo() != Undo::None`; `map_open` replaces the whole map and declares `Undo::None`, so the
  registry cannot name it — and it is the operation whose findings a reader most needs, since it is
  the one that brings a file's worth onto the screen. Named, with the reason, rather than a second
  list.

`stack::overlaps` is its own function rather than `blockers` per placement: `blockers` resolves a
guest once and every other placement once per call, so asking it about each placement is n
resolutions and n² tests where this is n resolutions and n² tests.

## Live proof on a real map

One `placement_set_yaw` on Sanctuary's `town` through the running editor and the MCP server, on a
scratch copy:

```
scratch: /tmp/emerge_probe/run-1792958440 load: 39.2
outcome: applied
checks: {
  "edge_faults": {"new": [], "new_total": 0, "total": 0},
  "overlaps":    {"new": [], "new_total": 0, "total": 781}
}
```

**781.** That number is not the feature's opinion, so it was cross-checked against the rule the editor
already enforces: for each pair, take one placement out of the map and ask `stack::blockers` — the
click path's own function — whether the other is among what it would refuse. It agreed on **781 of
781, 0 disagreements**. Sanctuary's town map holds 781 interpenetrating pairs that nothing could see
before this; they are pre-existing authoring (fences through fields, roads through houses, towers
through wall segments), not new breakage, and `new_total: 0` says this change made none of them.

That is the whole argument for the field: the map has been carrying 781 invisible overlaps and every
tool answer said "applied".

`a_preview_and_a_read_carry_no_checks` was written expecting to pass on both sides and does not: the
armed answer has no `checks` key at all before the change, so `answer.get("checks")` is `None` rather
than `Some(null)`. That is the same distinction the change is about, so it is recorded as a real
failing-before rather than glossed.

Plus three unit tests in `stack.rs` (a lapped pair named once; flush pieces left alone, which is
kitbashing's ordinary case; a lamp on its table not read as a table inside a table) and two in
`checks.rs` (the registry decides, `map_open` is the named exception; a standing finding is not new
while the total still counts it).

**One false start, recorded.** The first integration fixture placed the two pieces at `(0.25, 0.5)` and
`[0.75, 0.5]` and measured `total: 0`. `Fixture::place` writes `at` with `{:.1}`, so `0.25` lands at
`0.2` and the seam it was meant to test had a 0.05 m gap. The fixture is now flush at `0.5` and `1.0`.
The probe that found this is not in the tree.

## Deferred / open

- **E-079** — a piece standing in a doorway is reported by nothing. `stack::blocking`'s doc says why:
  `same_layer` is false for every heterogeneous pair, so nothing compares a crate against an opening's
  clearance, and `descriptor.rs`:667 records that nothing reads `Clearance`.
- **E-080** — a layout proposal does not report how varied it is: `range::measure` needs a solver grid
  and `grammar::learn` hands the editor back only the `Grammar`.
- **The editor's own `EdgeFaults` panel is a separate surface** and is not updated from an agent's
  answer. If it goes stale after an agent's change, that is its own item, not this one's.
