# 2026-10-26 rules-write: an agent can change a rule, and one Cmd+Z puts it back (E-081)

Focus: describe → set up → inspect (the agent tunes what generates the layout) · Commits: `c560a45` · Outcome: shipped

## Summary

`emerge_list_rules` shipped last iteration and answers what a project's rules say: Sanctuary's
`town_block` is a 17×17 block over 2 m cells with `weights: [(prefix: "town/house_", times: 100.0)]`,
`attempts: 64` and `seed: 600`. **An agent that can read those numbers and cannot change one has the
diagnosis and not the cure.** Every other tunable in this project is a registered operation
(`map_set_settings`, `label_set`, `map_rename`); the rules were a text editor.

`rules_set` closes that: `example` plus any of `cell`, `seed`, `attempts`, `no_empty` and `weights`,
written as text surgery so the file's comments survive, validated before the write, undone by one
Cmd+Z, and reachable from the keyboard as well as from an agent.

## Enhancement: a rule's numbers can be changed

**User-facing goal:** an agent that generated a layout and does not like it can change the number
that shaped it, without a person opening a text editor.

**Plan:** one registered operation over `assets/emerge/rules.ron`, using the text-surgery pattern
`map_rename` already established for this file; a `K` field so a person can do it too.
**Files:** `crates/bevy_emerge_mapper/src/ops.rs` (`rules_set`), `src/editor.rs` (the field and
`set_rule_seed`), `src/keys.rs` (`Action::SetRule` on `K`), `tests/a_rule_can_be_changed.rs` (new),
`tests/operations_have_two_front_ends.rs` (one row in the UI table).

**MCP:** `emerge_apply_operation {"operation": "rules_set", …}`. `Undo::Inverse`; a preview builds the
new file and throws it away, so `dry_run` answers with the block it would leave. No new tool —
`emerge_apply_operation` takes any registered operation by name, and `emerge_list_rules` is the read
beside it.

**Four things the tests and the live run taught me, each now pinned by a test:**

1. **A rule change recorded no map, so it could not be undone.** `emerge/operation_undo` finds a change
   by the map its recorded state names, so `after: None` meant *"nothing to undo: no change to the open
   map is still in effect"* — measured on this operation's own test. `after` now carries the open map:
   a rule is project data, but the map it is a rule *for* is the scope it is undone in.
2. **A whole-number weight lost its `.0`.** `50.0f64.to_string()` is `50`, so Sanctuary's
   `times: 100.0` came back `times: 50` — the number right and the spelling wrong, and the file's diff
   then carried an edit nobody made.
3. **The file is edited as text, not re-serialised.** A rules file is prose as well as numbers
   (`// houses should outnumber the road`), and `to_string_pretty` deletes every comment — the failure
   `ron_surgery` exists to prevent. The rewrite is parsed and compared with what the editor holds
   before it is written, so a surgery that touched the wrong block is a refusal.
4. **A person had no way to do it.** The parity test refused the operation with *"these operations have
   no UI entry point, so a person at the keyboard cannot do what an agent can: [\"rules_set\"]"*. `K`
   opens a one-number seed field and Enter dispatches the same operation, so the two are one change
   with one undo.

**Candidates considered and not chosen:**

- *Variety measurement* (E-080): needs `range::measure` to reach a `Map`, and `grammar::learn` hands the
  editor back only the `Grammar`. A structural adapter, not a report — and this iteration's rules write
  is the thing that makes tuning a rule worth measuring.
- *Turn checkpoints, one Cmd+Z per agent turn* (E-071): the Collaboration lens's next row, but it
  touches undo grouping across the whole operation layer.
- *`map_remove`* (E-066): `map_create` declares `Undo::None` because the faithful inverse of a create is
  a removal no operation carries. A whole new inverse shape, not a number.

## Live proof on the real project

Through the MCP server against a scratch copy of Sanctuary, editor running, `town` open:

```
outcome: applied | set the rule for `town_block`
weights on disk: ['weights: [(prefix: "town/house_", times: 50.0)],']
seed on disk:    ['seed: 1234,']
undo: applied
restored byte-for-byte: True
```

Every other line of `rules.ron` — the three `regions`, the 17×17 size, `border: Some("town/street")`,
the four-line `footprints` block, `attempts: 64` — came back identical, and the undo restored the file
exactly. **That byte-for-byte comparison is the claim worth having:** taking an agent's change back is
not itself an edit.

### The five questions, and what each turned up

| Question | Finding |
|---|---|
| **1. Can the text surgery corrupt the file?** | **Yes, and it did.** `set_field` located a field with `body.find("cell:")`, so a weight `prefix` of `"cell:x"` contains the characters `cell:` — and in a hand-edited file that writes `weights` before `cell`, `find` reached the *prefix* first, replaced inside the string, and produced `Expected end of string`. The whole-file parse check refused the write, so **the file survived and the operation was wrong**: it aimed at the wrong bytes and only the last check stood between the author and a broken rules file. Fixed by `field_at`, which finds a name only at the block's own bracket depth and outside any string. Regression test `a_field_name_inside_a_prefix_does_not_hijack_the_write` runs **both orders** — the editor's own field order, which passed by luck, and the hazard order, which fails without the fix. |
| **2. Undo.** | The inverse carries no `example`, and that is correct: `take_back` re-enters `commit` with the **inverse's own** parameters, and `commit` requires `example`, so an inverse without it would be refused outright — this would have been a failure, not a wrong write. It carries `example`, because the inverse is built with it. `after: {"map": …}` is the right scope for project data: `undo` selects a change by the map its recorded state names, and a rule's map is the one the author is looking at when they press Cmd+Z. Pinned by `undoing_a_rule_change_puts_the_number_back` and `a_change_and_its_undo_leave_the_file_unchanged`. |
| **3. Partial application.** | If `save_atomic` succeeds and the in-memory `ok_or_else` arm fires, the file changed and memory did not. **It is unreachable**: the arm looks the block up in the same `project.rules` that `rewritten` already found it in, with no borrow held across the write. Stated as reasoning, not as a test, because I could not construct an input that reaches it. |
| **4. Validation is library-free.** | `validate_numbers()` cannot know whether a rule names a descriptor the library lacks, so `rules_set` can write a rule that `Project::open` then refuses — the project would fail to load. **That is a real gap and it is not fixable here**: the server-side operation has no `Library` in `Ctx`, and loading one to check a name would be the full project open the editor exists to avoid. It is filed as **E-082** rather than left implied. What a caller *is* protected from is the block's own numbers: a `cell: 0.0`, `attempts: 0` or a 1×2 footprint is refused before the write. |
| **5. Lies.** | One, mine: the first commit message says *"all seven tests … failed"*, which was true of the seven that existed then; two more were added afterwards and the count is now nine. The report states each test's own status rather than a total. The code comments were checked against behaviour; the `K`→`L` change is recorded in the key ratchet's own note. |

## Deferred / open

- **E-080** — a layout proposal does not report how varied it is. Now that a rule can be tuned, the
  measurement that says whether the tuning helped is the missing half.
- **`footprints` are not writable by `rules_set`.** Their sizes, yaws and gaps are a different decision
  from a single number, and asking for one is a refusal rather than a silence. Its own item when
  someone needs it.
- **The `K` field sets only the seed.** `cell`, `attempts` and `no_empty` are reachable by an agent and
  not yet by a typed field; the parity rule is satisfied because the *operation* has a UI path, and a
  narrower field than the operation is a design choice stated here rather than hidden.
