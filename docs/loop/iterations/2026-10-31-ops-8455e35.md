## Bugs fixed
### #179: emerge_capture_sequence gives up when one status poll takes over 5 s
Must-fix: blocks yes (clip recording on a loaded Mac), common yes (3 of 3 attempts on bmb at load 17), no workaround but an idle machine.
Root cause: `main.rs` returned `refusal(&e)` on the first `Brp::call` error, and a call that ran out of its 5 s budget is an error. Fix (`brp.rs` `call_unless_busy`, new `sequence::wait_for_sequence`): a busy poll is counted and polled again; only the sequence's deadline ends the wait; a missing editor or a refusal still ends it at once.
Regression check: `crates/bevy_emerge_mcp/tests/a_slow_status_poll.rs` (2 tests, a stub editor on a local port). Failed before: the old loop, copied verbatim into a throwaway test against the same stub at a74d773, panicked with "the editor did not finish `emerge/capture_sequence_status` within 5 s, so the call was abandoned" (not kept; the new test needs `wait_for_sequence`, which does not exist at the base). Passes after: 2 passed in 5.3 s.

## Review
Reviewer (`reviewer` subagent, read-only, over `54cb78b..98f2627`) ran, and answered my five questions: (1) plan and commit refuse the same things, and the file is saved before success with the old lift restored on a failed save: yes; (2) undo exact: the inverse is exact but **the comparison was not**: yes, a defect (below); (3) the key keeps one log line and one undo entry per press and redraws the dependents on press and on Cmd+Z (`Undo::Logged` redraws every piece): yes; (4) `Undo::Lifted` fully gone, no save format or other crate used it: yes; (5) the ratchet only shrinks, 108 to 106, no other protected test code changed: yes.
Defect found (P2, confidence 0.8, reproduced): undo compares the lift its log line holds, read back from text, with the map's lift. An `f32` widened to `f64` prints with 17 digits and `serde_json`'s default parser can read it back one step off, so `emerge/operation_undo` refused "the map has changed outside the operation log" for a lift of 0.03 (`lift is 0.029999999329447746 and 0000-8796 left 0.029999999329447743`), and a person's Cmd+Z refuses the same way after a few presses of the 1/3 m step. Fixed in 7e73651: the lift is written as the `f32`'s shortest decimal in `after`, `state`, `state_of`, the plan and the inverse. Test `a_lift_that_an_f32_spells_in_many_digits_still_undoes` (11ecce7, 0.03, 0.11 and 1/3): failed at 11ecce7 with the refusal above, passes at 7e73651 (12 passed with `operations_have_two_front_ends::`). The reviewer says `placement_set_yaw` has the same pattern; its key values are whole degrees, so only an agent's fractional yaw would reach it. Not changed here.
