# 2026-10-30 view: every Update system reads this frame's pointer (#180)

Focus: #180 (the one unclaimed, workable bug issue) · Commits: c488d07, 43bf2cb, merge a45633e and this report · Machine: sib (Linux, RTX 3060, 16 cores) · Outcome: fixes only

## Summary
`a_person_shift_clicks_two_pieces_into_one_note` was flaky because `view::sense_pointer` wrote `Pointer` in `keys::Phase::Sense`, which orders it only before systems in a `Phase` set. The Note tool, the placement tools and their ghosts are in no set, so the executor could run a reader first, and a click then landed where the pointer had been the frame before. `sense_pointer` now runs in `RunFixedMainLoop` (`BeforeFixedMainLoop`): after `PreUpdate`, before every `Update` system.

## Bugs fixed
### #180: the second Shift-click is sometimes not picked
Must-fix: blocks y (the push gate runs this test and refused pushes at random), common y (3 runs in 24), no workaround n.
Root cause: a temporary print in `drive_note` (removed) showed that in the failing runs the second press read `ptr=(705.0, 405.3)`, which is the FIRST piece's pixel. The Shift-click toggled `site/wall@0` back out, giving `left: []`. One run read `ptr=None` on the first press. The window cursor was right both times; the reader had run before the writer.
Regression check: `the_pointer_is_read_before_anything_acts_on_it::a_reader_ordered_before_the_sense_phase_reads_this_frames_pointer` orders a probe `.before(keys::Phase::Sense)`, the worst place an unordered reader can land. Before the fix it failed with `left: [None]`, `right: [Some(Vec2(100.0, 200.0))]`. After the fix it passes. In the issue's acceptance batch (`editor every_list_follows_its_selection:: a_note a_person_shift note`, three batches at a time), the old code failed 3 of 24 runs and the new code passed 51 of 51 at load 29.
Scope: the fix covers every `Pointer` reader in `Update` by construction, with no reader re-ordered. Systems in `First` and `PreUpdate` (`surface::inject_clicks`, `retarget_pointer`) keep their documented one-frame latency. `bevy_fairy` writes `DebugCursor` in `PreUpdate` before `InputSystems`, so an agent's cursor and click in one frame now always meet.
