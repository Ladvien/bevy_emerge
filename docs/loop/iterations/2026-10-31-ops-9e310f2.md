## Enhancement: `pack_set_excluded`
Goal: an agent can say a folder of art is not what the kit is built from, and the key, the log and Cmd+Z agree with it.
Files: `ops.rs` (module, registry row, `UI_ENTRY_POINTS` row), `editor.rs` (`set_pack_excluded`; `adopt_library` and `carry_changes` carry `Project::policy`), `ops_brp.rs` (`put_back` carries a changed policy), `tiles.rs` (`exclude_pack` dispatches), `keys.rs` (`ExcludePack => pack_set_excluded`).
Proof: `tests/pack_set_excluded_is_an_operation.rs`. Its first four tests failed on the base (`no such operation` for an agent; the person's `Shift+R`: `one press of Shift+R is one log line`, left 0 right 1: the key wrote the file and logged nothing); the fifth, a restore undone after its folder is gone, was added for a review finding. 27 passed on big with `operations_have_two_front_ends::` (8), `piece_set_mount_is_an_operation::`, the undo tests and the existing `headless::the_excluded_band_opens_from_the_keyboard` (a real `Shift+R` on a heading). The real push gate (clippy and `cargo test --workspace`) ran on big.
MCP: `pack_set_excluded` (`pack`, `excluded`) through `grimoire_apply_operation`. Undo is the same operation flipped; the undo of a restore carries `put_back`, an undo-only form (`only_as_undo`) that re-lists the entry without asking the disk. Refused before anything is written: a name that is not a pack (empty, absolute, `.`/`..`/empty parts, a quote, a backslash, a control character: `rewrite_exclude` writes a string unescaped), a folder that is not under `assets/`, an exclusion already in force (listed, or left out by a folder above it), a restore of a pack nobody excluded, an unknown field, a missing one.
Decisions: `writes_library` is true for a kit-level write, so its line joins the Meshes history (Cmd+Z there takes it back, which `Shift+R` never had) and a bare `operation_undo` scopes past it. `after.id` is `pack:<pack>`, so a pack never shares an undo scope with a piece or a map of the same word. `.` (a root-level mesh's pack) is refused: `Policy::excludes` never matched it, so the key used to write an entry that did nothing.

## Review
`reviewer` subagent ran over the diff and answered the five questions: no P1. Five P3s, all fixed with a test or a changed assertion: (1) the undo of a restore was refused when the folder was gone (`put_back`, test `a_restore_is_undone_even_when_its_folder_is_gone`); (2) `editor::carry_changes` did not carry a changed policy (compare added); (3) the undo scope key could collide with a piece id or a map name (`pack:` prefix); (4) a pack under an already excluded folder was logged as a change that changed nothing (refused, naming the folder above); (5) the quote and backslash guard was shielded by the missing-folder check (the loop asserts the refusal says `is not a pack`). Noted, not changed: the exclusion list is read from memory rather than the file, as the old key did.
